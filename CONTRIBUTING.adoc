= Contributing
:hide-uri-scheme:

Thank you for contributing to importizer!
Improvements and bug fixes are gladly accepted, of course!
This page gets you from zero to a working build and hopefully a passing test run.
Everything else lives in link:/docs/[`docs/`].

== Quick start
=== 1. One-time setup
* *Linux:* Use Alpine Linux container, see xref:/docs/Building.adoc#linux-pre-setup[Linux pre-setup].
* *Windows:* Enable
https://learn.microsoft.com/en-us/windows/advanced-settings/developer-mode[Developer Mode] so
symbolic links work without Administrator privileges.
* *Git:* Run after cloning:
[,bash]
----
# Keep permission of files in scripts/ executable on commit
git config core.hooksPath .githooks

# Let pulls overwrite the moving continuous tag
git config --add remote.origin.fetch "+refs/tags/continuous:refs/tags/continuous"
----

=== 2. Environment setup
Run the setup script for your OS in *every new terminal*, before anything else.
It checks your tools and sets the environment variables the build relies on.
[,bash]
----
# Linux
distrobox enter importizer-alpine
. scripts/setup/Linux.bash

# MacOS
. scripts/setup/MacOS.bash

# Windows (PowerShell)
. scripts/setup/Windows.ps1
----
Note the leading `.`: scripts must be sourced, not executed.

=== 3. Build and test
[,bash]
----
# --preset importizer MUST ALWAYS be specified
cmake -B build -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=TRUE --preset importizer
cmake --build build --config Debug
ctest --test-dir build/tests -C Debug --progress --output-on-failure --schedule-random -j
----
The binary ends up in `build/importizer`.

== Opening pull requests
Constrain pull requests to individual changes where possible.
Simple changes are more easily integrated and tested.
Pull requests with many changes, where there are issues with one change in particular, will delay
the integration of all changes.

== LLM/AI policy
Only human conceived and created code and prose is accepted for now, no AI/LLM-generated code
allowed.

== Coding conventions

* 100-column per line limit for files, CLI outputs, and markup.

=== Naming
* *CMake targets and directories:* `kebab-case` (e.g., `3rd-party/`)
* *CMake user-defined (`-D`) variables :* `SNAKE_UPPERCASE` (e.g., `TRACE_BUILD`)
* *Environment variables:* `SNAKE_UPPERCASE` prefixed with `IMPORTIZER_` (e.g., `IMPORTIZER_OS`)

=== C{plus}{plus}
* See and make use of link:/.clangd[`.clangd`], link:/.clang-format[`.clang-format`],
link:/.clang-tidy[`.clang-tidy`].
Formating and linting will be checked in CI/CD.

=== CMake
* Only use generator expressions for build-time conditionals (e.g., `<$COMPILE_LANGUAGE:CXX>`).
* If a setting is for a specific library, put it in link:/CMakePresets.json[`CMakePresets.json`].
If it's for everything, put it in link:/DynPresets.cmake[`DynPresets.cmake`].

=== Scripts
* Use CMake to write scripts, if not possible, then make a folder and add scripts for all supported
OS'es (like `setup`).
* Environment setup scripts define these environment variables so you can use in other places:
** `IMPORTIZER_OS`: The operating system (`windows`, `linux`, `macos`)
** `IMPORTIZER_ARCH`: The architecture (`amd64`, `arm64`)
* For CI detection check if the environment variable `CI` was defined.

=== Markup
* Use https://asciidoc.org[AsciiDoc].
* Begin every sentence on a new line (one sentence per line).
However, wrap sentences at the column limit, but try not to because this means it's quite loooooong.
* Github turns on Asciidoctor's
https://docs.asciidoctor.org/asciidoctor/latest/safe-modes/#secure[SECURE safe mode], which disables
a few things, so keep that mind.
* Don't add a Table of Contents (TOC) unless there's a need to quickly jump to a section.
