== Running tests
Tests are disabled by default, but can be toggled via the `BUILD_TESTING` CMake option.
Follow the xref:/docs/Building.adoc#build-process[build process], but configure and build in
Debug mode with tests enabled.
[,bash]
----
ctest --test-dir build/tests -C Debug --progress --output-on-failure --schedule-random -j
----

== End-to-end (E2E) tests
Importizer uses a custom test runner (link:/src/testing/E2E.cc[`src/testing/E2E.cc`]) for end-to-end
tests.
To add a new test case, follow this format:
[,bash]
----
tests/my-new-feature/     # Subdirectory named after the test
├── Config.yml            # importizer's configuration
├── in/                   # Input files
├── ref/                  # Expected output files (don't add when not expecting valid output)
└── RefCLI.txt            # Expected CLI output
----

The CMake script detect changes in `tests/`, so your new test will be automatically picked up on the
next `cmake -B build` run.

== Unit tests
importizer uses https://github.com/doctest/doctest[doctest] (currently {doctest-v}) for unit
testing.
Unlike pre-built LibTooling, there's no pre-built doctest, but it's is still automatically
installed on configure (see link:/cmake/EnsureDoctest.cmake[`cmake/EnsureDoctest.cmake`]).
For unit tests:

* The test runner is link:/src/testing/Unit.cc[`src/testing/Unit.cc`] and it runs an entire test
suite by name.
* Tests suites (one per file) are in link:/src/testing/[`src/testing/`] (e.g.
link:/src/testing/FSTest.cc[`src/testing/FSTest.cc`] is the `FS` suite), and they test a family of
function (e.g. the `FS` suite tests filesystem utilities).
* Each test suite consists of test cases, where each test case should test 1 function.
* Each subcase should test an "aspect" of the function.

To add a new test case and subcases, simply follow
https://github.com/doctest/doctest/blob/master/doc/markdown/testcases.md[doctest's official guide].
Some rules to keep in mind, namely:

* Don't `#include <doctest/doctest.h>`, `#include "testing/Doctest.hh"`, which enforces:
** Correct doctest configuration macros.
** No syntatic sugar macros (`CHECK()`, `REQUIRE()`,...).
* For code that sets up the test "context", use `llvm::cantFail()`.
* For checks that must pass before others, use `REQUIRE_*()` macros.
* For independent checks, use `CHECK_*()` macros.
* Note that the macros require `bool` and contextual conversion does NOT work, so use the `ok()`
convenience functions.

To add a new test suite:

. Add a new file in link:/src/testing/[`src/testing/`] for the new suite, named
`<suite-name>Test.cc`.
. Add the suite name to the list in link:/tests/CMakeLists.txt[`tests/CMakeLists.txt`].
